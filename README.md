# 見積書・納品書・請求書

**1つの案件データから3種類をA4で印刷できます。インボイス制度に対応しています。**

👉 **[kaz-ma.github.io/invoice-jp/](https://kaz-ma.github.io/invoice-jp/)**

---

## 法律要件は一次ソースで確定させています

### 適格請求書（インボイス）の記載事項

[国税庁 インボイス制度の概要](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice_about.htm) の6項目が揃っているかを、画面で○×表示します。

① 相手方の氏名または名称 ／ ② 売手の氏名又は名称及び登録番号 ／ ③ 取引年月日 ／
④ 取引内容（軽減税率の対象品目である旨）／ ⑤ 税率ごとの対価の総額および適用税率 ／
⑥ 税率ごとに区分した消費税額等

### 消費税の端数処理は、税率ごとに1回だけ

国税庁 インボイス制度に関するQ&A 問13：

> 一の適格請求書に記載されている個々の商品ごとに消費税額等を計算し、1円未満の端数処理を行い、
> その合計額を消費税額等として記載することは**できません**。

**明細ごとに計算して足すのは、法律で認められていません。**

> 例：105円の行が3つ、税率10%
> 明細ごと → `floor(10.5)` × 3 = **30円**（誤り）
> 正しくは → `floor(315 × 0.1)` = **31円**

この1円差を、同梱の検査で固定しています。

### 登録番号のチェックデジット

[国税庁 法人番号の構成](https://www.houjin-bangou.nta.go.jp/documents/houjinbangounokousei.pdf)（財務省令2）の式で検証します。

```
検査用数字 = 9 − ( Σ(n=1〜12) Pn × Qn を 9 で除した余り )
Pn：基礎番号の最下位の桁を1桁目としたときの n 桁目の数字
Qn：n が奇数のとき 1、n が偶数のとき 2
```

**不一致でも入力は止めません。警告を出すだけです。**

### 源泉徴収

[国税庁 タックスアンサー No.2795](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2795.htm)。
100万円以下は `A × 10.21%`、超える部分は `(A − 100万円) × 20.42% + 102,100円`。

**どの明細が源泉徴収の対象かは、行ごとに指定できます。**
デザイン料は対象、システム開発や立替実費は対象外になることがあり、**一律に掛けると金額が狂います。**

> **法人が受け取る報酬は、原則として源泉徴収されません。**
> このツールは「これは対象だ」と断定しません。最終的な判断はご自身または税理士にご確認ください。

## そのほか

| | |
|---|---|
| 帳票 | 見積書 / 納品書 / 請求書。同じ案件データで切り替え |
| 採番 | `I-202610-001` 形式。月が変わると 001 に戻ります |
| 印刷 | **A4縦・余白15mm。** 明細が多いときは自動で改ページし、見出しを繰り返します |
| 保存 | このPCの中（localStorage）＋ JSONファイルの書き出し／読み込み |
| CSV | **BOM付きUTF-8。** Excelで開いても文字化けしません |

## 仕様

| | |
|---|---|
| ファイル | **単一HTML 1つ**。外部のCSS・JS・フォント・画像を1つも読みません |
| 通信 | **ゼロ。** 入力した内容はブラウザの外に出ません |
| 動かし方 | `index.html` をダブルクリック |
| 検査 | 画面の「セルフチェック」から49件の検査を実行できます |

**保存できない環境**（プライベートモードなど）では、起動時にその旨を表示し、JSONの書き出しに誘導します。**黙ってデータが消えることはありません。**
